# Классификация животных

Небольшая CNN на PyTorch. Обучение, проверка на отложенных изображениях,
предсказание для отдельного файла и веб-камеры. Зависимости управляются через
`uv`; точные версии записаны в `uv.lock`, Python 3.12 — в `.python-version`.

## Запуск

```bash
uv sync --locked
cp .env.example .env
uv run python main.py --help
```

По умолчанию устанавливается **CPU-сборка PyTorch**. Сервер базы данных не нужен:
история сохраняется в SQLite (`out/experiments.db`). Графики сохраняются в файлы,
поэтому обучение работает и без графического окружения.

Для обучения положите изображения в папки классов:

```text
data/animals-10/raw-img/
├── cane/
│   ├── image_001.jpg
│   └── ...
├── farfalla/
│   ├── image_001.jpg
│   └── ...
└── ...
```

Названия папок становятся названиями классов; итальянские названия Animals-10
автоматически не переводятся. Число выходов сети определяется числом классов.
Изображения должны находиться непосредственно в папках классов. Текстовые и
прочие неподдерживаемые файлы игнорируются. Нужны как минимум два класса и
достаточно изображений каждого класса для трёх выборок.

Если датасет лежит в другом месте, задайте `DATASET_FOLDER_PATH` в `.env`.
Затем запустите:

```bash
uv run python main.py train
uv run python main.py test
uv run python main.py predict /path/to/dog.jpg
```

`train` начинает новое обучение. По умолчанию 20% изображений откладываются для
теста; ещё 20% оставшихся изображений используются для валидации. Получаются
примерно 64% / 16% / 20% на обучение / валидацию / тест. Разбиение стратифицировано
по классам, начальное значение генератора — `SEED=42`.

Каждая эпоха сохраняется в `out/experiments/<run>/epoch_<number>/trained.pth`.
Лучшая эпоха **текущего запуска** выбирается по validation accuracy, при равенстве
— по validation loss, и копируется в `out/best/trained.pth`. Следующее обучение
обновляет эту копию; предыдущие эпохи остаются в своей папке эксперимента.
Тестовая выборка при выборе эпохи не используется.

`test` действительно запускает оценку модели. Он использует список тестовых файлов
из checkpoint, поэтому изменение `SEED` или долей выборок после обучения не меняет
состав теста. Сохраняйте содержимое этих файлов неизменным. Новые изображения
автоматически в сохранённый тест не добавляются. Дубликаты и почти одинаковые
кадры одного животного нужно убрать или сгруппировать до разбиения, иначе оценка
может оказаться завышенной.

В консоли и JSON-отчёте выводятся общая точность, точность каждого класса, сколько
раз модель предсказала каждый класс, и матрица ошибок: строки — истинные классы,
столбцы — предсказанные. Отчёт и график лежат в `out/plots/`.

Можно проверить конкретную сохранённую эпоху или использовать её для предсказания:

```bash
uv run python main.py test --model out/experiments/<run>/epoch_003/trained.pth
uv run python main.py predict /path/to/dog.jpg --model /path/to/trained.pth
```

## Что было неправильно в старом коде

- При обучении индексы классов назначались по порядку `os.listdir`, а при
  тестировании названия заново собирались через `set`. Соответствие «номер выхода
  → животное» могло поменяться: выход для собаки получал подпись бабочки.
  Теперь порядок стабилен, сохраняется вместе с весами и используется при загрузке.
- `test` не выполнял тестирование: вызовы были закомментированы, вместо них
  выбирался прежний результат из базы. Теперь результат рассчитывается заново.
- Истинный класс извлекался через `path.split('/')[4]`, что зависело от глубины
  пути. Теперь метка берётся из папки изображения и сопоставляется с checkpoint.
- В предсказании не было явного режима `eval()` / `inference_mode()`, а тест
  передавал изображение без размерности batch. Теперь оба варианта одиночного
  изображения обрабатываются явно. Сама по себе смена `eval()` не объясняет
  прежние 98%: в этой небольшой сети нет Dropout или BatchNorm.
- Loss сохранялся из остатка счётчика после печати каждых 2000 изображений,
  дополнительно делился на 2000 и не отражал среднее за эпоху. Теперь loss
  усредняется по всем изображениям, включая последний неполный batch.
- Обучение теперь идёт перемешанными мини-батчами. RGB сохраняется, в том числе
  для камеры, где исправлена конвертация OpenCV BGR → RGB. Формат предобработки
  записан вместе с весами.
- Исправлены CLI, создание папок, сохранение лучшей модели и команда удаления
  истории обучения, которая раньше вызывала удаление истории тестов.

**Уверенность 98% не означает ни 98% сходства животных, ни 98% точности модели.**
`predict` показывает softmax-уверенность и распределение по известным классам.
Модель может уверенно ошибаться и всегда выбирает один из обученных классов,
даже если на изображении другой объект. Точность измеряется командой `test` по
правильным ответам на отложенных изображениях. В исходной версии репозитория
процент выводился только как `Accuracy on test dataset`; без старых весов, данных
и полного вывода нельзя установить происхождение конкретного значения 98%.

**Старые `.pth`, содержащие только `state_dict`, требуют переобучения**:
в них нет названий классов, а новая предобработка сохраняет цвет вместо grayscale.
Такие файлы отклоняются с объяснением, чтобы не выдавать неправильно подписанные
предсказания.

Сеть остаётся небольшой CNN с входом 32×32. Эти исправления делают обучение и
оценку согласованными, но не гарантируют высокую точность на реальных животных.
В репозитории нет датасета и обученных весов; качество на Animals-10 здесь не измерено.

## Настройки и дополнительные возможности

В `.env` доступны `EPOCH_COUNT`, `BATCH_SIZE`, `LEARNING_RATE`, `MOMENTUM`, `SEED`,
`TEST_SIZE`, `VALIDATION_SIZE` и `NUM_WORKERS`. `VALIDATION_SIZE` задаётся как доля
данных, оставшихся после выделения теста. Настройки путей смотрите в `settings.py`.

Веб-камера требует OpenCV и графического окружения:

```bash
uv sync --locked --extra webcam
uv run --extra webcam python main.py webcam
```

Для PostgreSQL установите `uv sync --locked --extra postgres` и задайте `SQL_URL`
в `.env`. При запуске также передавайте `--extra postgres` в `uv run`, чтобы uv
сохранил установленный драйвер. Прежние переменные `POSTGRESS_USER`,
`POSTGRESS_PASSWORD`, `POSTGRESS_HOST`, `POSTGRESS_PORT`, `POSTGRES_DB` также
поддерживаются; явный `SQL_URL` имеет приоритет.

Для NVIDIA GPU замените CPU-индекс в `pyproject.toml` на индекс подходящей CUDA-сборки
для **обоих** пакетов (`torch` и `torchvision`), затем выполните `uv lock` и `uv sync`.
Варианты индексов и требования описаны в
[официальном руководстве uv для PyTorch](https://docs.astral.sh/uv/guides/integration/pytorch/).
При доступной CUDA код автоматически использует GPU. CPU-установка GPU не использует.

Очистка истории — только по отдельной команде:

```bash
uv run python main.py clear-test-data
uv run python main.py clear-training-data
```

Вторая команда удаляет записи об обучении и папку экспериментов, сохраняя
`out/best/`. Старое написание `clear-traning-data` оставлено как алиас.
Скрипт `scripts/clear_and_run.sh` выполняет обе очистки перед новым обучением и тестом.

## Проверки

```bash
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Тесты используют временные изображения и отдельную SQLite в памяти. Среди них:
сохранение порядка классов, загрузка модели, RGB/grayscale/RGBA, независимость
тестовой выборки от новых настроек, обучение → сохранение → тест → предсказание,
отклонение старых весов и сценарий «98% уверенности, но только 50% точности».
Проверяется и средний loss при неполном последнем batch.

Предсказания выполняются по стандартной схеме PyTorch:
[загрузка `state_dict` и режим `eval()`](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html).
При обучении в
[`CrossEntropyLoss`](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)
передаются logits; softmax применяется только для отображения уверенности.
